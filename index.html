DevOps Practice — Vol. 03

Install Docker
with Ansible
Playbook

This playbook automates Docker installation, ensures the service is persistent across reboots, and configures user permissions for non-root Docker management.

ansible docker.io ansible.builtin.apt ansible.builtin.service ansible.builtin.user aws ec2 wsl2 idempotent
// 01 — The Playbook
docker-install.yaml
docker-install.yaml
12345 678910 1112131415 1617181920 2122232425
---

- name: install docker on ec2 instances
  hosts: all
  become: true

  tasks:

    # Task 1 — Install Docker
    - name: Install Docker
      ansible.builtin.apt:
        name: docker.io
        state: present
        update_cache: yes

    # Task 2 — Start & enable Docker
    - name: Start Docker
      ansible.builtin.service:
        name: docker
        state: started
        enabled: yes

    # Task 3 — Non-root Docker access
    - name: Add user to Docker group
      ansible.builtin.user:
        name: ubuntu
        groups: docker
        append: yes
🎯
hosts: all
Runs against every host in the inventory — Docker gets installed on all EC2 instances at once.
⬆️
become: true
Escalates to sudo — required to install packages and manage system services on remote hosts.
📦
ansible.builtin.apt
Installs docker.io with a fresh package cache update in a single task.
⚙️
ansible.builtin.service
Starts Docker and sets enabled: yes so it auto-starts after every reboot.
👤
ansible.builtin.user
Adds ubuntu to the docker group. append: yes keeps existing group memberships intact.
// 02 — Execution Flow
How to Run It
1
Verify Connectivity
Confirm Ansible can reach all EC2 hosts via passwordless SSH before running anything.
ansible all -i inventory.ini -m ping
2
Dry Run First
Check mode simulates every task without making changes — catch errors safely before committing.
ansible-playbook -i inventory.ini docker-install.yaml --check
3
Run the Playbook
Ansible installs docker.io, starts the service, and adds the ubuntu user to the docker group on all hosts.
ansible-playbook -i inventory.ini docker-install.yaml
4
Verify on the Server
SSH into any EC2 instance and confirm Docker is installed and the user can run it without sudo.
docker --version && docker run hello-world
5
Idempotency Check
Run the playbook again — Ansible detects Docker is already installed and reports ok, not changed.
ansible-playbook -i inventory.ini docker-install.yaml
// 03 — Modules Used
What Each Module Does
📦
ansible.builtin.apt
Package Install
Installs docker.io from Ubuntu repos. update_cache: yes refreshes the apt index first.
⚙️
ansible.builtin.service
Service Manager
Starts the Docker daemon and sets enabled: yes so it survives every server reboot automatically.
👤
ansible.builtin.user
User Permissions
Adds ubuntu to the docker group so Docker commands run without sudo. append: yes is critical here.
🔁
idempotency
Safe to Re-run
Run this playbook 10 times — the result is always the same. Ansible only acts when the system isn't already in the desired state.
⬆️
become: true
Sudo Escalation
All three tasks need root — installing packages, starting services, and modifying user groups all require privilege escalation.
🎯
hosts: all
All Hosts at Once
No need to target groups — Docker gets deployed to every node in the inventory in a single playbook run.
